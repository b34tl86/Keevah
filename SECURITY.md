# Security policy

## Supported versions

| Version | Security fixes |
|---|---|
| The latest 1.x release | Yes |
| Earlier 1.x releases | No: please update to the latest |
| 0.9 and earlier | No |

## Reporting a vulnerability

Please report security problems privately. **Never open a public issue or discussion about one.**

- **On GitHub:** use [private vulnerability reporting](https://github.com/b34tl86/Keevah-AI/security/advisories/new). You'll also find it under this repository's **Security** tab, as **Report a vulnerability**. Only you and TechTrust can see the report.
- **Or through TechTrust:** get in touch at [techtrust.ae](https://techtrust.ae) and say it's a security report.

Tell us:

- the Keevah version, and the system it runs on;
- what the problem is, and what someone could do with it;
- how to reproduce it: the steps, or a proof of concept.

Please don't include real customer data, call recordings or transcripts, and test only Keevah installations you run yourself.

## What happens next

We'll confirm we've received your report, look into it and keep you posted. When a fix is ready it goes out in a release, and the release notes say what was fixed. Please keep the problem to yourself until then. If you'd like to be credited, say so in your report.

## How Keevah protects data

- Transcripts, call summaries, messages and phone system passwords are encrypted on the server.
- Every organisation sees only its own calls, people and settings.
- Two-step sign-in, account lockout after repeated wrong passwords, and an audit log that can't be edited.
- Backups are encrypted to a key that is kept off the server.
